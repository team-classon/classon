# Classon 기획 요약

> 원문: 「Classon 프로젝트 개요 v2」. 이 문서는 개발에 필요한 내용만 추려 정리한 것이다.
> 기능 단위 상세는 `feature-spec.md`, 테이블은 `erd.md`를 본다.

## 1. 한 줄 소개

영어 지문을 넣으면 AI가 단어장·지문 분석서·수업 자료를 만들고,
강사는 그 자료로 수업하고, 학생의 단어시험·모의고사 성적을 관리해 학부모 리포트까지 만드는 학원 내부용 플랫폼.

## 2. 사용자와 권한

| 사용자 | 로그인 | 하는 일 |
|---|---|---|
| 관리자 (ADMIN) | O | 공식 원본 지문 업로드, AI 자료 생성·미리보기·확정, 원본 삭제, 부적절한 공유 자료 삭제, 강사 계정·반·학생 관리 |
| 강사 (TEACHER) | O | 자료 검색·다운로드, 수정본 업로드·공유, 개인 자료 생성·공유, 단어시험 제작·채점, 모의고사 성적 입력, 학생 메모, 분석 검수, 학부모 리포트 생성 |
| 학부모 | X | 강사가 전달한 리포트를 받아 보기만 함 (시스템 밖) |

**학생 정보 접근 (확정)**
- 검색·조회: 모든 강사 가능
- 수정, 메모 작성, 성적 입력·확정: 담당 반 강사와 관리자만

## 3. 자료 체계

```
공식 원본 지문 (관리자)                 강사 개인 원본 (강사)
   │                                       │
   ├─ 필수 어휘·단어장 (VOCAB)              ├─ 단어장
   ├─ 지문 분석서 (ANALYSIS)                ├─ 지문 분석서
   └─ 수업 자료 (LESSON)                    └─ 수업 자료
        │
        └─ 강사 수정본 (김OO Ver1, Ver2 …)
```

- 공식 계통과 개인 계통은 서로 독립적이다.
- 필수 어휘와 단어장은 같은 자료다.
- 단어장은 단어 단위로 DB에 저장해 단어시험 출제에 쓴다.

### 3.1 공식 자료 흐름 (확정)

1. 관리자가 원본 지문 업로드 (+ 추가 프롬프트 선택 입력)
2. AI가 자료 3종 생성 (자료별로 성공·실패가 다를 수 있음)
3. 관리자가 미리보기로 확인 → 필요하면 **자료별로** 재생성 또는 간단 수정
4. 관리자가 **3종을 한 번에** 확정 → DB 저장, 자료찾기에 공개
5. 확정 전 자료는 강사에게 보이지 않는다

- 확정된 공식 자료는 다시 생성하지 않는다. 늘어나는 것은 강사 수정본뿐이다.
- 새 자료가 필요하면 새 버전 원본을 올린다. 이름 옆에 "(수정본)"처럼 표시한다. 기존 원본·자료·수정본은 그대로 남는다.
- 원본을 삭제하면 그 원본의 자료 3종과 모든 수정본이 같이 삭제된다. 삭제 전에 영향받는 수정본 수를 보여 준다.
- 교과서 지문의 단원 구조 차이는 LLM 판단(프롬프트)에 맡긴다.

### 3.2 강사 수정본 (확정)

- 공식 자료를 docx로 내려받아 직접 수정한 뒤 업로드한다. 앱 안에 편집기는 없다.
- docx만 업로드할 수 있다.
- 업로드할 때마다 새 수정본이 생긴다. 파일명 규칙: `기존파일명(수정내용)_홍길동강사Ver1`
  (홍길동 강사가 그 자료에 처음 올린 수정본이 Ver1)
- 기본은 비공개(작성자만 열람). 공유하면 자료찾기에 공개되고, 언제든 공유 해제할 수 있다.
- 공유를 해제하면 다른 강사의 열람·다운로드를 바로 막는다. 이미 받은 파일은 관여하지 않는다.
- 공유해도 소유권·수정 권한은 넘어가지 않는다.
- 다른 강사의 수정본을 기반으로 수정본을 만들 수 없다.
- 삭제: 작성자 본인, 관리자.
- 강사 간 공유 알림 기능은 만들지 않는다 (카카오톡 등 외부 소통 사용).

### 3.3 강사 개인 자료 (확정)

- 강사가 자기 파일을 올리고 공식 자료와 같은 흐름(추가 프롬프트 → 생성 → 미리보기 → 확정)으로 자료를 만든다.
- 확정 후 "공유하시겠습니까?" 모달을 띄운다. 공유하면 자료찾기의 **개인자료 공유** 칸에 올라간다.
- 단어장 추가 기능은 별도 기획 (향후).

### 3.4 AI 생성 상태

- 원본 전체 상태: 생성 중(GENERATING) → 확인 대기(REVIEW) → 확정(CONFIRMED) / 실패(FAILED)
- 자료별 상태: 생성 중 → 성공 / 실패
- 실패 이유는 사용자에게 전달하지 않는다 (보통 토큰 부족 등).

## 4. 단어시험 (확정)

### 4.1 시험지 제작
- 강사가 단어장을 1개 이상 골라 출제 범위를 정한다.
- 공식 단어장과, "기타 자료 추가"를 통해 강사 개인 자료 단어장도 고를 수 있다.
- 시험지는 PDF로 만들어 내려받는다. **시험지와 정답지는 서버에 저장하지 않는다.**
- 구체적인 문제 유형(영→한, 한→영 등)은 세부 기획에서 정한다.

### 4.2 채점
1. 강사가 학생 답안 스캔본을 올린다. 스캔본 1개 = 학생 1명의 시험지 1장.
2. AI가 답안을 읽고, 단어의 뜻을 판단해 학생 답이 맞는지 1차 채점한다.
3. 판독이 불확실한 답안은 AI가 판단하지 않고 강사 확인으로 넘긴다.
4. 강사가 단어채점 화면에서 2차 채점(확인·수정)을 하고 확정한다.
5. 확정된 점수만 학생 성적에 반영된다.

- 단어장과 답안지를 따로 저장하지 않아도 되는 이유: AI 판단을 바로 반영하지 않고 강사가 2차 판단을 하기 때문.
- 단어시험은 점수 중심으로 관리한다.

## 5. 모의고사·분석·리포트

- 모의고사 성적은 모달에서 **점수와 틀린 문항 번호**를 입력한다.
- 문항 번호 → 유형 매핑은 "2019년 이후 모의고사는 같은 번호면 같은 유형" 전제를 따른다. 2019년 이전 시험은 거의 쓰지 않는다.
- 유형별 정답률·오답률로 취약 유형을 판정한다. **모의고사 2회 이상** 입력돼야 분석한다.
- AI 학습 분석 결과는 강사가 확인·수정·삭제한 뒤에만 리포트에 쓴다. 강사 확인 없이 학부모에게 가지 않는다.
- 리포트는 docx(강사가 받아서 수정 가능)와 PDF로 만든다.
- 과거 성적과 리포트는 전부 보존한다.
- 학부모 단체 메시지는 향후 확장 기능 (현재 범위 아님).

## 6. 개인정보·저작권 원칙 (초안, 운영 전 법률 검토 필요)

- AI에는 학생 식별 정보(이름, 연락처, 학부모 연락처, 학교명)를 보내지 않는다. 내부 ID와 성적만.
- 강사 메모는 AI 전송 전에 학생 이름과 전화번호 패턴을 마스킹한다. 입력 화면에 실명·연락처 금지 안내.
- AI 호출 로그에 메모 원문과 학생 식별 정보를 저장하지 않는다.
- 사용하는 AI 서비스가 입력 데이터를 학습에 쓰지 않도록 설정·계약 조건을 확인한다.
- 업로드 파일은 비공개 저장소, 로그인 사용자만 접근.
- 학생 이름이 있는 단어시험 스캔본은 채점 확정 후 보관 기간이 지나면 삭제 (기간 미정).
- 학생은 soft delete. 보존 기간 후 식별 정보 파기 (절차 미정).
- 원본·파생 자료는 학원 구성원에게만 제공. 외부 공개 링크·외부 공유 기능은 만들지 않는다.
- 개인 자료 업로드 시 "이용 권한이 있는 자료만" 안내와 책임 고지.
- 개발·테스트·시연·GitHub에는 실제 교재·기출 지문을 쓰지 않는다.
- 저작권 문제가 생기면 원본 삭제(파생물 일괄 삭제)로 대응한다.

## 7. 결정 기록

| 주제 | 결정 |
|---|---|
| 공식 자료 확정 단위 | 자료별 재생성 가능, 확정은 3종 한 번에 |
| 새 원본 버전 | 기존 자료 유지, 이름 옆 "(수정본)" 표시 |
| 원본 삭제 | 파생 자료·수정본 전체 삭제 |
| 수정본 이름 | `기존파일명(수정내용)_홍길동강사Ver1` |
| 수정본 확장자 | docx만 |
| 공유 해제 | 즉시 차단, 이미 받은 파일은 관여 안 함 |
| 개인 자료 공유 | 확정 후 공유 여부 모달 → 자료찾기 개인자료 공유 칸 |
| 교과서 등록 단위 | LLM 판단에 맡김 |
| 학생 조회 범위 | 조회는 전체 강사, 수정은 담당 반만 |
| 반 배정 이력 | 저장하지 않음 (성적은 학생에 연결돼 유지) |
| 단어시험지·정답지 | 저장하지 않음, AI 1차 + 강사 2차 채점 |
| 취약 유형 분석 조건 | 모의고사 2회 이상 |
| 과거 성적·리포트 | 전체 보존 |
| 강사 퇴사 | 계정 비활성화, 자료 유지 |
| AI 생성 횟수·길이 제한 | 보류. 개발 완료 후 진행 (사용량 기록은 처음부터 남김) |
| 브랜치 전략 | 조직 레포에서 브랜치 방식, 개발 완료 후 개인 레포로 복사 |

## 8. 미결정 사항 (구현 전에 물어볼 것)

| 주제 | 현재 가정 | 영향 범위 |
|---|---|---|
| 로그인 방식 (세션 / JWT) | JWT 추천 (프론트가 별도 레포일 경우) | 보안 설정 전체 |
| 계정 발급 방식 | 관리자가 강사 계정을 발급, 회원가입 없음, 단일 학원 | users, 관리자 화면 |

| 학생 개인정보 보존 기간·파기 절차 | 미정 | 파기 배치 |
